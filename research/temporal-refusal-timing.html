Trajectory-sensitive refusal timing

When does a model begin to refuse, and what information has it already supplied?

The endpoint problem

A conversation can end with a refusal and still contain useful harmful assistance in earlier turns. Conversely, a late safe answer should not be counted as evidence that every prior response was safe. Endpoint-only scoring discards the sequence that connects those states.

The central idea is simple: represent an interaction as a series of turn-level labels rather than one terminal label. This makes at least three questions visible:

  • When does refusal or another safety response first become stable?
  • How much harmful information appears before that point?
  • Do matched ways of presenting the same objective produce different trajectories?

Matched trajectories

Each source objective is represented through three presentation formats. The direct arm tests a single explicit request. The staged-direct arm decomposes the request across multiple turns while keeping intent explicit. The semantically cloaked arm spreads context and capability-relevant pieces across turns. Staged direct is intended to separate the effect of length from the effect of cloaking.

“Same objective” is necessary but not sufficient for a matched design. Arms also need budget parity, equivalent opportunities to answer, frozen construction procedures, and comparable horizons. Otherwise the trajectory format changes both the treatment of interest and the resources available to the attack.

Metric anatomy

Stable activation time

The notebook’s threshold-crossing field records the first stable activation of a configured safety or refusal score. It is not an “unsafe trigger rate.” In conceptual form:

SATk = first turn t where safety score ≥ threshold for k comparable turns

With k=2, a one-turn direct trajectory can never meet the definition. A direct value of zero and a multi-turn value of 0.20 therefore do not measure an unsafe-vs-safe difference; they reflect a structural mismatch in metric eligibility.

Cumulative harmful exposure

A stronger follow-up separates safety activation from harmful assistance. Let each turn receive a human-calibrated harm label. Cumulative Harmful Exposure (CHE) then aggregates substantial harm across a fixed horizon:

CHE(T) = Σt=1…T 1{ turn-level harm ht ≥ substantial }

This quantity answers a different question from final-turn attack success. A trajectory may have final ASR=0 because the last answer refuses, while CHE>0 because earlier turns exposed substantial information.

What the pilot establishes

The current public artifact establishes that the pipeline can load prompt data, construct trajectory variants, call configured models, collect turn-level judgments, calculate metrics, and emit provenance and gate reports. That is an engineering result.

It does not establish a behavioral effect. Generated benchmark outputs are excluded from version control by default, and the inspected pilot fails multiple claim gates. Numerical fragments from that run should be treated as diagnostic evidence attached to a specific artifact, not as a general model-safety result.

Monitor audit

The inspected monitor output contains 7 true positives, 2 false positives, and 50 false negatives. Those event counts imply 77.8% precision but only 12.3% recall. A 5.8% latency overhead was also reported. True negatives were not available in the reviewed summary, so accuracy, specificity, and false-positive rate cannot be reconstructed.

Reading the metrics correctly

Safety activation, harmful assistance, and cross-condition differences are distinct quantities. The wording below records earlier misinterpretations so they cannot be mistaken for findings.

A claim-eligible follow-up

The revised study direction compares trajectory-level harmful exposure with strong single-turn baselines under audited budget parity. It treats null results as informative: if endpoint ASR and CHE agree once resources are matched, that bounds when endpoint evaluation is sufficient.

  1. Lock the estimand. Predefine CHE, final-turn ASR, fixed horizon, and a paired objective-model unit.
  2. Match budgets. Account separately for target calls and total attacker resources, including prompt construction and judging.
  3. Separate model roles. Target models must not judge their own outputs; construction and judge roles remain disjoint.
  4. Validate labels. Use two independent model judges plus a representative bilingual or domain-qualified human audit as required.
  5. Preserve every run. Version outputs, seeds, configs, failures, provider metadata, and code revision.
  6. Publish against gates. If validity thresholds fail, publish a measurement-validity report rather than a behavioral claim.

Current conclusion

This is a promising benchmark question and a functioning pilot pipeline. The inspected data are not strong enough to claim that cloaked trajectories cause delayed refusal or greater harmful exposure.
