Mechanistic interpretability: from features to causes

Finding a readable feature is a starting point. How do we test whether it actually explains a model’s behavior?

The representation problem

Neural networks transform tokens into high-dimensional activation vectors. We can record those vectors exactly, but coordinates are not guaranteed to correspond to human concepts. A neuron can respond to many unrelated patterns, and one concept can be distributed across many neurons.

Mechanistic interpretability asks for more than a readable story. A useful explanation should identify a component, predict when it activates, survive tests on new data, and change behavior in the predicted direction when intervened upon.

Superposition

A model may need to represent more useful features than it has cleanly dedicated dimensions. Superposition describes a regime in which features share representational directions. When feature demand is sparse—only a few features are active for any one input—overlap can still be computationally useful.

Superposition complicates neuron-level interpretation. If several features share a direction, inspecting one neuron may recover a mixture. It also motivates methods that learn an overcomplete dictionary: more candidate feature directions than the original activation dimension.

Sparse autoencoders

A sparse autoencoder (SAE) learns to reconstruct a model activation using a larger set of latent features while encouraging only a small subset to activate on each example. In simplified form:

features f(x) = ReLU(Wencx + benc)
reconstruction x̂ = Wdecf(x) + bdec
objective = reconstruction error + λ · sparsity penalty

The reconstruction term asks the dictionary to preserve information. The sparsity term discourages every feature from activating everywhere. Changing dictionary size, sparsity coefficient, activation data, or training procedure changes the learned decomposition.

Why sparsity is not interpretability

A sparse code can still contain difficult features. One feature may combine several meanings (polysemanticity); one meaning may be split across several features; rare concepts may never appear in training data; and reconstruction can omit behaviorally important information.

Evaluating a feature dictionary

No single metric establishes interpretability. Reconstruction, sparsity, and semantic coherence answer different questions and can trade off against one another.

Fidelity

How well does the reconstruction preserve activations, downstream loss, and behavior?

Sparsity

How many latents activate per example, and how many dictionary elements remain dead?

Meaning

Can a description predict activation on held-out positives, negatives, and adversarial counterexamples?

Feature labeling should be treated as model-building. A proposed description predicts which new texts activate the feature. The test set should include near misses and counterexamples, not only the most activating examples used to invent the label.

From correlation to causality

High activation on a concept can reflect input, output, a downstream consequence, or a correlated context. Causal methods perturb internal states and test whether model behavior changes as predicted.

Activation association
Locate components that correlate with a behavior. Useful for hypothesis generation, weakest for mechanism claims.
Ablation
Remove or suppress a component and measure target behavior plus broad capability side effects.
Activation patching
Replace an activation in a corrupted run with one from a clean run to localize information flow.
Steering
Increase or decrease a direction and test dose response, specificity, reversibility, and out-of-distribution effects.
Mechanistic account
Connect components into a computation that predicts behavior across inputs and survives causal tests.

Controls are essential. A large intervention can change output simply by damaging the representation. Useful controls include random directions of matched norm, neighboring features, unrelated prompts, multiple intervention strengths, and general-capability checks.

Reproduction roadmap

A bounded first project should prefer a small open model and a narrow question over an impressive but unauditable feature atlas.

  1. Select an artifact. Fix an open model, layer, activation site, dataset, and exact software revision.
  2. Train or load an SAE. Record dictionary size, sparsity objective, token sample, optimizer, and checkpoint.
  3. Measure fidelity. Report reconstruction error, loss recovered, activation sparsity, and dead-feature rate on held-out data.
  4. Generate hypotheses. Inspect high-activating examples, but store candidate descriptions separately from validation data.
  5. Validate descriptions. Predict activation on held-out positives, negatives, and counterexamples.
  6. Intervene. Run ablation or steering with matched controls and report target effects, nulls, and side effects.
  7. Release the run. Publish code, configs, checkpoints where licensing permits, and enough data to reproduce every figure.
